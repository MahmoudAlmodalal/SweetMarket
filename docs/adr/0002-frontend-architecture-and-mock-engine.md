# 0002 - المعمارية التقنية للواجهة الأمامية ومحاكاة البيانات المطابقة لشاشات Stitch

## السياق والقرار (Context & Decision)
1. **البيئة التقنية الأساسية (Architecture Stack):**
   - اعتماد **Next.js (App Router)**، **React**، **TypeScript**، و**Tailwind CSS** مع ضبط كامل لاتجاه اللغة العربية (`dir="rtl"` ولغة `lang="ar"`).
   - استخدام ثيم كاندي لوز المعتمد في Stitch (`Crème Boutique Confectionery`): الخطوط (`El Messiri` للعناوين، `IBM Plex Sans Arabic` للواجهات والأسعار)، ومصفوفة ألوان الباستيل الدوّارة للبطاقات (Gelato Pastels).
2. **محرك البيانات الوهمية المستمر (Mock Data & Storage Persistence):**
   - تنفيذ طبقة بيانات وهمية (`Mock Data Repositories`) مع محاكاة تأخير الشبكة الطبيعي (200-300ms) وتخزين الحالات محلياً في `localStorage` (`candy_cart_v1` و `candy_orders_v1` و `candy_admin_session_v1`).
   - هذا يضمن اختبار كافة تدفقات التطبيق الحقيقية (إضافة للسلة، إتمام طلب كزائر، استخراج رقم التتبع، متابعة الطلب من الزبون، واستقبال وتحديث حالة الطلب داخل لوحة الإدارة) بدون الحاجة إلى خادم خلفي فعلي في هذه المرحلة.
3. **أولويات التنفيذ (Implementation Phasing):**
   - التركيز في الدفعة الأولى على شاشات واجهة الزبون السبع (SCR-01 إلى SCR-07) لمطابقة شاشات Stitch المرجعية بدقة متناهية، يتبعها مباشرة استكمال شاشات لوحة الإدارة (SCR-11 إلى SCR-20).

## العواقب (Consequences)
- تصبح الواجهة مستقلة تماماً وقابلة للاختبار والعرض الحي الفوري.
- عند بناء الـ Backend لاحقاً، يتم استبدال طبقة الـ Mock Repositories باستدعاءات الـ API دون تعديل بنية المكونات أو واجهات المستخدم.
