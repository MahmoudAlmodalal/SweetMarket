# المعايير الهندسية للبنية التحتية المشتركة في الواجهة الخلفية

## السياق والقرار
لبناء أساس برمجي موحد ومتوافق تماماً مع عقود الواجهة الأمامية و`API.md`، تقرر اعتماد:
1. **توليد المعرفات الفريدة (Prefixed IDs):** صيغة البادئة النصية المقروءة (`<prefix>_<nanoid/urlsafe>`, بطول 32 محرفاً مع فهرسة) بدلاً من الأرقام التسلسلية المباشرة لكافة الكيانات.
2. **تطبيع الهواتف الفلسطينية:** اعتماد صيغة 10 أرقام محلية موحدة (`059xxxxxxx` أو `056xxxxxxx`) وتجريد أي بادئات دولية (`+970`, `+972`) قبل الحفظ في قاعدة البيانات.
3. **تغليف الردود و camelCase:** دمج التغليف القياسي `{ success: true, data, meta }` مع تحويل `camelCase` آلياً عبر `UnifiedCamelCaseJSONRenderer` و `CamelCaseJSONParser`.
4. **توحيد معالجة الأخطاء:** استخدام `custom_exception_handler` لإرجاع كود خطأ محدد (`code`) ورسالة وتفاصيل الحقول المهيكلة `{ success: false, error: { code, message, details } }`.
5. **معايير الترقيم (Pagination):** استخدام معاملات `page` و `limit` (الافتراضي: 20، الأقصى: 100) مع إعادة البيانات الوصفية `{ page, limit, totalItems, totalPages }`.
6. **إعدادات أمان JWT:** تحديد عمر رمز الوصول (Access Token) بـ 60 دقيقة ورمز التحديث (Refresh Token) بـ 7 أيام مع تفعيل التدوير والقائمة السوداء (Rotation & Blacklist).
7. **محرك التخزين المؤقت (Cache):** اعتماد `LocMemCache` افتراضياً للتطوير والاختبارات مع دعم التبديل البيئي إلى Redis للإنتاج.
